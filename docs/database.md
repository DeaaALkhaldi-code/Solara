# PostgreSQL database

PostgreSQL 18 is the local/CI target. Drizzle schema: backend/src/db/schema.ts. Committed SQL and migration metadata: backend/drizzle/. node-postgres provides the backend connection pool.

## Tables

| Table | Purpose | Relationships / key constraints |
| --- | --- | --- |
| users | Identity, normalized unique email, phone, role, optional password hash | UUID primary key; customer/admin enum; normalized email check |
| sessions | Hashed session token and expiration | Owner FK cascades on deletion; unique token hash; expiry after creation |
| categories | Product grouping | Unique slug |
| products | Catalog, images, specifications, integer price, currency, stock | Category FK; unique slug; nonnegative price/stock; currency check |
| estimates | Calculator inputs, assumptions, version, results | Owner FK; JSONB for versioned technical data |
| estimate_products | Recommended products and quantities | Estimate/product FKs; unique pair; positive quantity |
| orders | Owner, contact/delivery snapshot, total, currency, status, tracking reference | Owner FK; nonnegative total; unique optional tracking reference |
| order_items | Product reference and order-time name/price snapshot | Order/product FKs; positive quantity; nonnegative unit price |
| tickets | Owner, optional order/product, issue, subject, description, status | Owner/order/product FKs; status enum |
| ticket_replies | Customer-visible conversation | Ticket/author FKs |
| ticket_notes | Internal staff conversation | Separate table; ticket/author FKs |

UUIDs are generated by PostgreSQL. Timestamps use timezone-aware columns; API mappers serialize them to ISO strings. Drizzle updates updatedAt when ORM update queries omit it; raw SQL writers must set it explicitly.

Money uses integer minor units with an explicit uppercase three-letter currency and a maximum of 2,147,483,647 per field. The service must respect the currency's decimal convention and enforce one currency per order. Energy contracts name their units explicitly (Wh, W, hours, days).

Indexes cover owner/date queries, admin status queues, catalog category/availability filters, conversation timelines, and referencing foreign keys.

## Ownership and write rules

Foreign keys enforce referential integrity, not application authorization. Private queries must filter by the authenticated owner. Only authorized staff may manage products/users/orders or access internal notes. Verify that an order linked to a ticket belongs to its owner.

Create an order and its line items in a single transaction. Calculate totals from current product prices on the backend; reject mixed currencies and duplicate/invalid product selections. Preserve names/unit prices in line items. Stock reservation/locking and permitted status transitions must be implemented with the ordering feature.

Products and users with business history are restricted from deletion. Prefer deactivation/anonymization policies when implementing management. Child line items/recommendations/conversations cascade only with their parent. Do not expose raw user/session/ticket-note rows in customer responses.

Cart state remains a frontend concern initially. Checkout submits only product IDs, quantities, and contact/address data. Saved carts can be added later if cross-device persistence is required.

Calculator inputs/results use JSONB because the calculation is versioned; validate the corresponding shared Zod schemas before saving. Recommendations use relational rows. No engineering formulas are implemented or certified.

## Database commands

- npm run db:up: start the local Docker PostgreSQL service and wait for readiness.
- npm run db:generate: generate a migration after editing schema.
- npm run db:check: validate migration history metadata (not live schema drift).
- npm run db:migrate: apply committed migrations using DATABASE_URL.
- npm run db:migrate:production: apply migrations using compiled backend code.
- npm run db:seed: idempotently insert reference categories, without user accounts.
- npm run db:studio: inspect the configured development database.
- npm run db:down: stop the local service, retaining the named data volume.

Do not edit an applied migration: add a new migration. Schema generation needs no DB URL; migration/seed/studio commands require a configured one. Never point tests at production. CI uses a disposable PostgreSQL service; local migration tests use an embedded PostgreSQL engine via PGlite.

This is a fresh PostgreSQL schema. No existing database was connected, converted, reset, or removed.
